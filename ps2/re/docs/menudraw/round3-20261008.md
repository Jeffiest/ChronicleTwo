## Local rectangle helpers

The previous 13 differences occupy +0x43C..+0x488, covering the form alpha
test and first texture-rectangle copy after `GetNowPosRGBA`. Retail uses
v1/a2 where the entry native draft uses v0/v1. The documented direct part
indexing, texture field, signed shadow conversion, and meaningful local
lifetimes from [round 1](round1-20261008.md) are retained.

The retail symbol table identifies both corner-conversion helpers as LOCAL:

| Function | Address | Size | Purpose |
| --- | --- | --- | --- |
| `ConvMGIRECTtoINTtbl__F9mgRect_i_Pi` | 0x2216D0 | 0x60 | Expand an integer origin/size rectangle into four x/y corners. |
| `ConvMGFRECTtoFLOATtbl__F9mgRect_f_Pf` | 0x221730 | 0x60 | Expand a floating origin/size rectangle into four x/y corners. |

Each helper takes its rectangle by value and writes eight coordinates:
left/top, left+width/top, left+width/top+height, and left/top+height.
The source previously gave both helpers external linkage. Correcting the
integer helper's declaration and definition to `static` resolves the
caller's 13 differences, while leaving the helper's own instructions exact.
The float helper is also made `static` to agree with its retail binding.

| Linkage/type variant | Form differences / 1020 | Native inventory |
| --- | --- | --- |
| Entry: both helpers externally linked | 13 | 195 match, 3 differ |
| Integer helper static | 0 | 196 match, 2 differ |
| Float helper static | 13 | 195 match, 3 differ |
| Both helpers static, retained | 0 | 196 match, 2 differ |

This is an evidenced linkage correction to existing functions. It is not
evidence for changing `GetNowPosRGBA`'s supported int return, the rectangle
layout, or any form-part field. A const-qualified by-value integer rectangle
instead shortens its helper to 0x5C and introduces 16/24 helper differences;
that variant is rejected even where its caller matches. No new helper,
manual copy-assignment member, or compiler-profile selector is introduced.
The experiment establishes MWCC's allocation response to the local helper;
it does not establish the compiler's internal reason for that response.

## Drawing behavior and native data

Fresh `decompile.sh`/m2c output agrees with the existing documented form,
part, texture-info, rectangle, colour and effect types. The function skips
inactive, hidden and function-info parts, applies per-axis vibration to
their destination rectangles, combines form and part colour channels, and
dispatches primitives using `MENUFORMPARTS_DTYPE`. Cursor and explicit CLUT
reload parts take their early paths before the general texture lookup.
Other branches draw sprites, repeated/effected polygons, numbers and their
shadows, frames, item icons, pictures, gradient fills, random lines, and
memo content. The caller's texture-block reference tracks the reload state.
The purpose and layout documentation from rounds 1 and 2 remains applicable;
no shared type or API changes are needed.

The promotion replaces its three eight-byte assembly-supplied initial
position objects with zero-initialized native definitions of their existing
types. All three retail symbols and native definitions have LOCAL binding:

| Object | Address | Type and purpose |
| --- | --- | --- |
| `at_3428` | 0x37DAC8 | `menu_cursor_pos`: two float coordinates copied before placing a cursor. |
| `at_3527` | 0x37DAD0 | `menu_line_origin`: two int coordinates copied before generating random lines. |
| `at_3531` | 0x37DAD8 | `menu_memo_pos`: two float coordinates copied before drawing a memo. |

The types are already documented in this translation unit. The definitions
are static objects with no dynamic initialization; their original
`INCLUDE_BSS` entries are removed. Replacing the local copies with direct
arrays while merely removing those entries produced 329 complete-object
relocation problems: unnamed small-BSS pieces no longer resolved as these
objects. Keeping the real typed objects supplies the supported data owners
and passes the whole-object check. There is no added game state or dummy
local storage.

The main-menu texture name is the seven-byte, zero-terminated `"mnmain"`
string at 0x36FAE0 (`at_2238`, padded to eight bytes). All four uses in this
unit now contain that literal directly, and the extern declaration and
assembly rodata entry are removed. The existing matched main-frame and
special-form callers remain exact.

`ITEM_ID_SPECTOL` and `ITEM_ID_BOILED_FISH` name the two item identities handled specially by the TRS
part branch. A spectrumised attachment, 0xB9, uses `etc_info[2]` as its
original-item icon and selects spectrum mode. Boiled fish, 0x1AA, similarly
uses the original fish's icon and selects its palette mode. These meanings
agree with the existing userdata analysis of `GetSpectolNo` and the boiled
fish item-number storage. `MENU_ICON_MODE` names the existing DrawOneItem
modes: normal (0), spectrum (1), dimmed (2), and boiled fish (3). The local
mode is typed as this enum; DrawOneItem's existing int API is unchanged.

The `item_effect` pointer is persistent state across the part loop: it
starts null, a spectrum TRS part assigns its effect, and DrawOneItem consumes
the current pointer. Following parts can retain that value. It is not an
unused scratch local and must not be removed or reset at each iteration.
Private probes that removed it, or reassigned it to a fill-branch effect,
change that behavior and are discarded. The retained source keeps its
original lifetime and assignments.

The whole promoted function uses typed part indexing, named fields, genuine
gradient pointers and existing drawing APIs. The earlier PlusF, FormPart
and PartTex steering wrappers remain absent. No raw pointer walk, type pun,
manual vtable assignment, dead store, goto, replacement assembly, or new
Satan's Fiddle row is used.
